# 기존 모임 회원 식별 수정과 프론트 연결 안내

## 수정 이유와 범위

기존 운동·게임·공동구매·옛 스터디는 생성 시 실제 회원을 자동 참여시키지만, 참여·취소에서는 임시 회원 ID `-1`을 사용했다. 같은 계정이 생성 후 참여하면 실제 ID와 `-1`이 별도 인원으로 기록되는 문제를 격리 API에서 재현했다.

이제 기존 모임 참여·취소도 공통 인증과 활성 회원 검사를 거친 실제 회원 ID를 전달한다. 신규 프로젝트·스터디 규칙, 관리자 참여 정책, 기존 개설자 취소 금지 정책은 유지한다. 기존 DB의 `-1` 데이터는 자동 변경하거나 삭제하지 않는다.

## 소희님 프론트 수정 사항

1. `frontend/src/hooks/meetup/useMeetups.js`
   - 기존 모임의 `member_id === -1` 판단을 제거한다.
   - 인증인가 기능에서 확인한 현재 회원 ID와 `/api/recruits/{id}/members`의 `member_id`를 비교한다. 숫자·문자열 형식은 명시적으로 맞춘다.
   - 신규 프로젝트·스터디는 상세 응답의 `my_application.application_status`로 확정·대기를 구분한다. 대기자는 확정 참여자 목록에 없으므로 목록만으로 판단하지 않는다.
   - 비로그인·로그아웃·사용자 전환 때 이전 사용자의 참여 상태를 비운다. 오류가 나면 임의로 참여 성공 상태로 바꾸지 않는다.
2. `frontend/src/services/meetupApi.js`
   - 공통 API 요청 함수를 사용하고 기존 쿠키 인증 전달을 확인한다. 본문에 임의 회원 ID를 추가하지 않는다.
   - `POST /api/recruits/{id}/join`, `DELETE /api/recruits/{id}/join` 주소·기존 성공 응답은 유지한다.
   - 비로그인은 401, 비활성 회원은 403이다. 기존 모임의 중복 참여·미참여 취소는 400, 개설자 취소는 403이다. 신규 프로그램의 기존 오류 계약은 유지한다.
3. `frontend/src/components/meetup/MeetupMemberList.jsx`
   - 행 구분은 회원 ID 기준으로 유지한다. 표시 이름이 같다고 같은 회원으로 판단하거나 중복 행을 화면에서 숨겨 DB 문제를 감추지 않는다.

## 통합 테스트

- 개설자가 참여 버튼을 눌러도 인원은 늘지 않는다.
- 다른 회원이 참여하면 1명만 늘고 반복 신청은 거절된다.
- 취소하면 본인만 빠진다. 다른 사람과 개설자는 유지된다.
- 새로고침·계정 전환·비로그인에서 버튼과 인원 상태를 확인한다.
- 기존 데이터에 `-1`이 남아 있으면 이 수정만으로 인원에서 사라지지 않는다. 모임 ID와 참여 기록을 확인하고 팀과 합의한 테스트 데이터만 정리한다.

백엔드 수정은 프론트 수정 완료를 의미하지 않는다. 실제 로그인 화면 통합 테스트는 소희님 코드 연결 후 수행한다.
