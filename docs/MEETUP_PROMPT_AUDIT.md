# 개발 프롬프트 재검토 결과

기준 파일: 민지님이 전달한 `PlayMate_민지_모임백엔드_Codex_최종명령프롬프트.md`.
작업 브랜치: `feature/33-meetup-backend-function-fix`, 최신 develop `3de523e` 반영.

**프롬프트의 모든 기능이 실제 운영에 연결된 상태는 아닙니다.** 아래에서 내부 구현·테스트와 운영 연결을 구분합니다.

## 재검토 중 발견해 수정한 부분

1. **연장 우회 방지:** 다른 신청자가 없는 모임에서 마감 후/첫 연장 후 일반 PATCH로 일정을 바꿀 수 있는 여지를 차단했습니다. 공식 연장 절차와 횟수 검증을 거쳐야 합니다.
2. **상세 응답 보완:** 본인 이탈 횟수·제한 발효 시각/사유(`my_eligibility`), 팀장 본인 여부(`is_leader`), 연장 날짜 범위/남은 횟수(`extension_window`), 예외 결정 유효 버전(`exception_start`)을 추가했습니다. 타인의 이탈 이력은 공개하지 않습니다.
3. **미달 처리의 범위:** 인원·기술을 충족한 정상 프로젝트에 미달 전용 팀장 취소/예외 시작 조작을 허용하지 않게 했습니다. 화면 권한과 서버 검사를 함께 맞췄습니다.
4. **커리큘럼 과도한 차단 해소:** 미정인 관리자 생성 모임의 편집 기준을 USER 생성 스터디까지 확대해 저장을 503으로 막던 부분을 수정했습니다. 사용자 생성은 개설자만 저장하며 버전 충돌을 검사합니다. 관리자 생성 권한은 자동 부여하지 않습니다.
5. **결과물 단계:** OUTPUT의 중간/최종 단계 누락을 스키마에서 거절합니다. WEEKLY_CHECK는 주차를 요구하고 단계는 null입니다.
6. **수동 테스트 준비:** 실제 서비스·Repository·라우터를 사용하되, 가상 회원/기술 사전·메모리 DB로 분리한 Swagger 서버를 추가했습니다. 실제 인증/DB 검증과 혼동하지 않도록 별도 포트와 명칭을 사용합니다.

## 지금 직접 확인할 수 있는 것

`docs/MEETUP_MANUAL_API_TEST.md`의 별도 8001 Swagger에서 신규 생성·신청·대기·취소·승격·팀장·연장·가상 시작을 확인할 수 있습니다.
실제 로그인·공유 DB·기존 화면·파일 업로드·봇·XP 지급이 완료된 뜻은 아닙니다. 수동 앱은 `backend/tests/recruit`에만 있으며 운영 main.py에는 포함되지 않습니다.

## 운영 연결을 보류한 근거

명령 프롬프트 C/F절은 기존 공통 인증·권한 변경을 협의 전 보류하고, 준비 전에는 신규 주소를 실제 서버에 연결하지 않고 격리 검증/문서를 완료하도록 정합니다. 공유 DB 적용은 별도 승인이 필요한 범위입니다. 그래서 테스트 편의를 위해 운영 서버에 가상 인증이나 fake 기술 사전을 넣지 않았습니다.

미정 개인 활동 인정 주체·공통 XP 보상 유형/한도·회수 정책·마이페이지 커리어·스토리지·봇 기능을 임의 구현한 것으로 보고하지 않습니다. 이 보류 조건은 확정된 신청/팀장/연장 업무 규칙을 다시 미정으로 돌린다는 뜻이 아닙니다.

## 최종 검증

신규 모임/수동 API 및 기존 모임 마감·소셜·게시판 회귀: **110개 통과, 전용 PostgreSQL 미제공 1개 스킵**.
수동 서버의 `/docs`는 실제 HTTP 200, `/__test__/guide`는 ISOLATED_SQLITE·실제 로그인 미검증을 반환하는 것도 확인했습니다. 이 확인은 실제 PostgreSQL/OAuth 연결 검증이 아닙니다.

이후 Docker Desktop 실행 후 별도 PostgreSQL 16.15에서 실제 마이그레이션 SQL·마지막 자리 동시 신청·동일 회원 중복 신청 **3개 검증을 추가로 통과**했습니다. PostgreSQL 기본 검증 보류는 해소됐습니다. 세부 범위는 `docs/MEETUP_POSTGRES_VERIFICATION.md`를 참고합니다. 공유 DB 적용/OAuth/운영 연결은 여전히 별도입니다.

후속 2단계 연결 검증: 실제 main 앱의 기존/신규 분기와 PostgreSQL API 흐름까지 포함해 **124 passed**. 실제 OAuth는 대역으로 구분했습니다. 공유 DB 접속은 읽기 전용 확인 단계에서 인증 실패가 반환돼 DDL/기능 활성화는 실행하지 않았습니다. 공통 기술 사전은 사용자가 아직 미정이라고 확인했습니다.
