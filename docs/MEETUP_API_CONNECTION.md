# 2단계 API 연결 결과

최신 상태(2026-10-26): 사용자가 `.env`를 갱신한 뒤 DB 접속이 정상화됐습니다. 별도 승인 후 새 테이블 9개를 공유 DB에 적용하고 재접속으로 검증했습니다. 아래의 DB 인증 실패/DDL 미적용 설명은 이전 점검 기록이며, 현재 적용 이력은 `docs/MEETUP_MIGRATION_APPLIED.md`를 기준으로 합니다. 새 기능 활성화 설정과 실제 로그인 검증은 별도입니다.

브랜치: `feature/33-meetup-backend-function-fix`

**연결 코드와 격리/실제 PostgreSQL 통합 검증을 완료했습니다. 실제 공유 DB에서 새 기능을 활성화하지는 않았습니다.**

## 연결한 방식

- 기존 `/api/recruits` 주소를 유지했습니다.
- 기본 주소는 `recruit.py` → `RecruitDispatchService`가 기존/신규 서비스를 선택합니다.
- 기존 운동·게임·공동구매·옛 스터디는 기존 생성/조회/참여 동작을 유지합니다.
- 신규 스터디/프로젝트는 `recruit_programs` 기록으로 구분하고 새 신청/권한/시간 규칙을 적용합니다.
- 새 생성 스키마 검증 실패를 기존 스키마의 필드 무시로 성공시키지 않습니다.
- 기존 목록 배열·순서를 유지하고 신규 행만 추가 필드로 확장합니다. category 필터는 기존/신규 모두 지원합니다.
- 기존 공개 조회를 유지합니다. 익명 사용자에게는 신청서·제재 정보·쓰기 권한을 반환하지 않습니다.
- 새 모임 쓰기는 공통 인증의 실제 회원을 사용합니다. 기존 `-1` 경로의 전면 변경은 다음 인증 단계의 협의 범위입니다.
- 연장·예외 시작·취소·중도 종료·커리큘럼·활동은 겹치지 않는 확장 주소만 main에 등록했습니다.
- 기능을 비활성화해도 신규 모임을 기존 수정/참여 규칙으로 우회하지 못하게 했습니다.
- 새 모임 논리 삭제는 개설자의 모집 중 초안·타인 신청 이력 없음 조건에서만 허용합니다. 단체 취소와 혼용하지 않습니다.

## 검증 결과

실행:

```powershell
& .\.venv\Scripts\python.exe -m pytest backend/tests/recruit backend/tests/test_join_deadline.py backend/tests/test_recruit_social.py backend/tests/test_board_api.py -q
```

전용 PostgreSQL 컨테이너를 연결한 조건에서 **124개 모두 통과**했습니다.
PostgreSQL 검사는 4개: 실제 SQL 파일 실행/인덱스, 마지막 자리 동시 신청, 동일 회원 동시 신청, main API의 생성·공개 조회·신청·대기 흐름입니다.
기존 4종 모임 생성/조회·새 모임의 권한/삭제 보호·기능 중지 시 우회 차단·중복 라우트 방지·기존 소셜/게시판 회귀도 포함합니다.

인증은 명시적인 테스트 대역입니다. 실제 Discord 세션/공유 DB 권한 검증 완료가 아닙니다.
기존 8001 수동 서버는 이전에 실행한 메모리 테스트 프로세스이며 코드 변경이 자동 반영되지 않습니다. 수동 서버를 재시작하면 main과 같은 모임 분기 라우터로 테스트할 수 있습니다. 운영 설정과 가상 인증은 별도입니다.

## 활성화 설정과 현재 제약

`ENABLE_RECRUIT_PROGRAMS`의 기본값은 false입니다. 기존 기능은 유지하며 새 기능은 503으로 준비 미완료를 안내합니다. 이 파일이나 코드가 개인 `.env`를 자동 수정하지 않습니다.

실제 활성화에는 다음이 필요합니다.

1. 공유 DB 접속 정보가 유효해야 합니다.
2. 대상 DB를 확인하고 팀과 합의 후 `database/sql/20261026_recruit_programs.sql`을 적용합니다.
3. 적용을 확인한 다음 `ENABLE_RECRUIT_PROGRAMS=true`로 설정하고 해당 백엔드 프로세스를 재시작합니다.
4. 프로젝트 생성에는 실제 공통 기술 ID/이름 사전 어댑터가 필요합니다.

현재 확인:

- 기존 개인 설정으로 공유 DB 테이블을 읽기 전용으로 확인하려 했으나 서버에서 **DB 인증 실패**를 반환했습니다. 테이블 존재 여부를 확인하지 못했고, 데이터/DDL 변경은 하지 않았습니다.
- `.env`의 DB 설정 키는 존재하며 중복 키와 상속 환경의 덮어쓰기는 확인되지 않았습니다. 계정/비밀번호 등 최신 접속 정보 확인이 필요합니다. 비밀값은 출력/문서화하지 않았습니다.
- 사용자가 공통 기술 사전은 아직 미정이라고 확인했습니다. 실제 프로젝트 생성은 사전 연결 전까지 503으로 보류합니다. 임의 번호를 운영 기술 ID로 넣지 않습니다.
- 실제 스토리지/XP/봇/예약 실행 연결은 이 단계에서 완료한 것으로 보고하지 않습니다.

따라서 **2단계는 코드 연결/통합 검증 완료, 실제 공유 DB 활성화 대기**입니다. 현재 상태를 ‘실서비스에서 전부 동작 완료’로 표시하면 안 됩니다.

개인 `.env` 수정·공유 DB SQL 적용·커밋·푸시·PR은 실행하지 않았습니다.
