# 취업 게시판 통합 037

범위: 후기·톡톡·라운지·연구소. 뉴스, 채용공고, 수집기, 뉴스 스크랩,
통계 대시보드, 모임은 변경하지 않는다. Discord 공지 기록도 유지한다.

## 최종 저장 구조

- `posts`: 공통 익명 설정, career_category/subcategory, career_details(JSONB), poll_options(JSONB).
  직무·카테고리 검색용 인덱스와 유형별 DB 검증을 둔다.
- `post_attachments`: 게시판 이미지와 톡톡 첨부. 기존 두 URL 체계의 ID 충돌은
  `(attachment_scope, attachment_id)` 복합키로 구분한다. API ID와 저장 파일은 그대로다.
- `career_lab_poll_votes`: 기존 PK/회원 FK 및 데이터 유지. 게시글 FK와 선택지 검증 트리거를 둔다.

기존 상세 5개, 선택지, 톡톡 첨부, 게시판 이미지의 물리 테이블 8개를 제거하고
공통 첨부 1개를 추가해 순감소는 7개다. 기존 이름의 8개 호환 뷰는 데이터 복사본이 아니다.
현재 서버·봇·XP·마이페이지의 기존 SQL이 이 뷰를 통해 같은 데이터에 접근한다.
신규 작성·수정은 `career_content_writer.py`에서 posts 한 행에 원자적으로 저장한다.
API 응답 및 프론트 메뉴 변경은 필요하지 않다.

## 적용

1. 최신 코드 및 실물 스키마 확인. `inspect_career_consolidation.py --env-file PATH`는 읽기 전용이다.
2. PostgreSQL 18 로컬 일회용 DB에 `test_career_consolidation.py` 실행.
   이 스크립트는 localhost의 **playmate_career_test** DB에만 허용되며 public 스키마를 초기화한다.
3. `rehearse_career_consolidation.py`로 public 스키마를 읽기 전용 dump하고,
   새 로컬 DB에 복원해 037을 적용한다. backup-dir은 반드시 Git 작업 폴더 밖에 둔다.
4. 검증 보고서와 SQL의 SHA-256이 일치할 때만 `apply_career_consolidation.py` 실행.
   적용 직전 새 백업을 생성·복원 검증하고 그 보고서를 사용한다.
   이 명령은 실제 대상 DB를 변경하므로 env-file을 정확히 지정해야 한다.
5. 038_career_compat_permissions.sql도 적용해 호환 함수의 PUBLIC 실행 권한을 제거한다.
   기존 트리거 호출은 유지하며, 일반 계정이 임의 테이블에 소유자 권한 트리거를 붙이는 것을 차단한다.
   적용 스크립트의 `--permissions-only`로 이 단계를 실행할 수 있다.
   이후 새 백엔드 코드를 배포한다. 기존 코드도 호환 뷰의 쓰기 트리거로 계속 동작한다.
6. RDS 생성 후 기존 000~036 스키마와 데이터가 준비된 대상에 같은 037·038을 검증·적용한다.
   기존 마이그레이션을 무작정 재실행하지 않는다. 특히 031은 별도 데이터 준비 조건이 있다.

037은 한 트랜잭션이며 재실행용 SQL이 아니다. 기존 타입·FK·하위 분류가 예상과 다르면 중단한다.
대상 테이블에 최대 10초 동안 잠금을 기다리며 잠금 획득 후 이관 중 요청이 대기할 수 있다.
비대상 테이블을 같은 트랜잭션 스냅샷에서 비교하고 모든 기존 투표 및 호환 뷰의 필드값을 검증한다.
DROP CASCADE는 사용하지 않아 미확인 외부 의존성이 있으면 전체 작업을 롤백한다.

## 데이터 보존 및 복구

취업 익명 여부는 기존 화면이 사용하던 career_posts 값을 기준으로 posts에 이관한다.
선택지 ID·투표·첨부 ID·파일 경로·생성 시각을 보존한다. 투표 후 선택지·유형 변경은 DB에서 막는다.
옛 스크립트의 상세 테이블 직접 DELETE/TRUNCATE는 더 이상 지원하지 않는다. 게시글 삭제는 posts로 수행한다.

코드 롤백은 기존 SQL을 지원하는 호환 뷰 덕분에 DB를 되돌리지 않아도 가능하다.
물리 DB 복구가 필요한 경우 검증된 dump를 새 DB에 복원하고 컷오버한다.
백업 이후 쓰기가 있었다면 그대로 덮어 복원하지 말고 해당 변경을 먼저 보존·재적용한다.
호환 뷰와 트리거를 제거하는 작업은 모든 서버·봇·관리 스크립트 전환 후 별도 변경으로 진행한다.

## 검증

실제 PostgreSQL에서 구형/신형 작성·수정, 네 메뉴 목록·상세, 익명/비공개 회사명,
첨부 ID 충돌·업로드·삭제·정렬, 투표 중복·잘못된 선택지·투표 후 변경 거부를 확인한다.
뉴스와 채용 데이터를 포함한 비대상 테이블은 내용 해시와 행 수로 비교한다.
